Abstract

This project applies Proximal Policy Optimization (PPO) to train a simulated go-kart to autonomously discover an optimal racing line around a closed circuit track. The agent is given no explicit knowledge of the correct path. Instead it receives rewards for forward progress and speed, and learns through interaction with the environment in a custom PyBullet simulation.

The observation space uses ray-cast wall distances rather than a centreline lookahead, allowing the agent to navigate by spatial awareness rather than following a guide. Progress is tracked using polyline arc-length projection, which correctly handles lap boundaries and generalises to any track shape. After 700,000 training timesteps across 4 parallel environments, the agent consistently completes laps and shows emergent racing line behaviour through corners.

Overview of the Project

This project was completed as an extension of AI for Robotics (41118). The challenge was to train a simulated go-kart to autonomously discover an optimal racing line around a circuit using reinforcement learning. The agent had to learn purely through environment interaction, receiving rewards for speed and forward progress while being penalised for leaving the track.

Functional Requirements

Environment and Track

  • Simulated circuit built in PyBullet using a rounded rectangle layout with straight wall sections and circular corner arcs built directly from circle geometry
  • Physical wall collisions enforced by static PyBullet box segments
  • Car spawned at a fixed starting position on the track

Observation Space

  • 7 ray-cast wall distances spread across a 180° forward arc
  • Current forward speed
  • Normalised lap progress
  • Previous smoothed steering value

Reward Function

  • Forward arc-length progress reward scaled by 15.0 per metre
  • Speed reward scaled by 3.0 per m/s
  • Off-track penalty of -50.0
  • Step penalty of -0.05 per frame
  • Steering smoothness penalty of -2.5 per unit of steering change

Training Pipeline

  • PPO algorithm from Stable-Baselines3 with MlpPolicy
  • 4 parallel environments using SubprocVecEnv
  • TensorBoard logging for training monitoring
  • Checkpoint saving every 50,000 steps
  • Path visualisation outputting a top-down driven line image per episode

Design Iterations

Iteration 1 — Initial Environment and PPO Setup

The project was altered from the second assignment. The goal, obstacle, and scenario logic were removed and replaced with a closed circuit track. The first fix required was the car spawn position. The original car.py hardcoded basePosition=[0, 0, 0.1] meaning the car always spawned at the origin. This was fixed by adding base_position and base_orientation arguments to the Car constructor. The track was built using direct geometry, straight walls as single long boxes and corner walls as arc segments computed directly from circle equations.

The initial observation space used a centreline lookahead point converted into car-relative coordinates using PyBullet's invertTransform and multiplyTransforms. Progress was tracked using the angle of the car's position on the centreline ellipse.

PPO was configured with the following hyperparameters:

  • learning_rate = 0.0003
  • n_steps = 512
  • batch_size = 256
  • ent_coef = 0.01
  • total_timesteps = 300,000
  • n_envs = 4

Two track shapes were explored. The first was an elliptical oval using TRACK_OUTER_A=12, TRACK_OUTER_B=8, TRACK_INNER_A=8, TRACK_INNER_B=4. The second was a rounded rectangle with STRAIGHT_LEN=14, CORNER_RADIUS=5, TRACK_WIDTH=5 which provided clearer straight sections and tighter hairpin corners. The rounded rectangle was selected as the primary track going forward.

Iteration 2 — Centreline Hugging Diagnosis and Fix

After initial training the agent consistently followed the centreline regardless of reward shaping. The lookahead target was computed directly from the centreline, so the agent was always being steered toward the centre of the track regardless of what the reward function said. The observation was redesigned to remove the centreline target entirely and replace it with 7 ray-cast wall distances spread from -90° to +90° relative to the car. The agent now navigated by sensing the available space on each side rather than following a guide point, giving it the freedom to find the faster line through corners.

The number of rays was increased from an initial 5 to 7 to provide better spatial resolution through corners. max_dist was set to 10.0m to give adequate lookahead on the straights.

Iteration 3 — Progress Tracking Overhaul

The original progress tracking used the angular position of the car projected onto the centreline ellipse. The same angle could correspond to multiple positions on a non-circular track, making the measurement ambiguous. It was also entirely tied to the ellipse formula and would break on any other track shape.

This was replaced with polyline arc-length projection. The centreline was discretised into 200 points forming a closed polyline. Each step the car's position was projected onto the nearest segment of the polyline, returning a distance s in metres from the start. Progress delta was computed as curr_s - prev_s with wraparound handling at the lap boundary. Total laps were derived from total_distance / total_length. Only positive deltas were accumulated to prevent reverse reward farming.

Iteration 4 — Steering Oscillation Fix

After switching to ray-cast observations the agent completed laps but exhibited continuous left-right oscillation. Three changes were made together to address this.

First, exponential moving average smoothing was applied to the steering output before passing it to the car. The smoothed steering was computed each step as 0.6 × prev + 0.4 × requested, meaning the car physically could not execute instantaneous large steering changes. Second, a 2-step rolling average was applied to the raw ray distances using a deque buffer, smoothing flickering in the ray readings caused by wall segment edges. Third, a steering smoothness penalty of -2.5 × |current_steering - prev_steering| was added to the reward function. The previous steering value was also added to the observation array so the network could condition its next action on what it had just done. _actionRepeat was reduced from 50 to 20 to allow finer control corrections.

Testing the Code

TensorBoard Output

The training was monitored using TensorBoard throughout each iteration. The ep_rew_mean graph shows the average episode reward per episode over time. A successful training run shows this value climbing from negative numbers in early training toward a stable positive value as the agent learns to complete laps. The ep_len_mean graph shows average episode length — a decreasing value means the agent is completing laps faster.

The entropy loss graph shows how random the agent's policy is over time. A high entropy early in training indicates broad exploration. As training progresses entropy should decrease as the policy becomes more confident. A healthy training run shows a gradual entropy decrease that stabilises alongside the reward convergence.

Evaluation, Feedback, and Reflection

Accomplishments and Achievements

The project delivered a functioning RL pipeline for autonomous racing line discovery in simulation. The agent learned to complete laps consistently with the reward curve converging positively. The most significant technical achievement was redesigning the observation space from lookahead to ray-cast, removing the implicit guidance preventing the agent from exploring the full track width. The arc-length projection progress tracking system correctly handled lap boundaries and generalised to any track shape. The path visualisation tool gave immediate visual feedback after each training run.

Challenges and Obstacles

The centreline hugging problem was the most persistent challenge. The initial hypothesis that the reward function was at fault was incorrect. The root cause was in the observation space, not the reward. Identifying this required stepping back from reward shaping entirely and reconsidering what information the agent was actually receiving.

Steering oscillation was reduced significantly through action smoothing and a smoothness penalty but never fully eliminated. Track design was also a recurring challenge. Several layouts were attempted and abandoned before settling on the rounded rectangle with direct geometry wall construction, which proved reliable but limited the visibility of the racing line due to its symmetric corner shape.

Design Decisions and Impact

Using ray-cast wall distances instead of a centreline lookahead was the most impactful decision, shifting the agent from following a guide to navigating by spatial awareness. Arc-length projection replaced the angular progress method which was unreliable near the lap boundary and tied to ellipse geometry. Action smoothing as a physical constraint was more effective than the reward penalty alone for reducing oscillation since it enforced the behaviour directly rather than incentivising it.

If continuing this project, a more complex track would be the first priority. The symmetric corners limit how far the racing line can deviate from centre, which is the primary thing the project aims to demonstrate.
